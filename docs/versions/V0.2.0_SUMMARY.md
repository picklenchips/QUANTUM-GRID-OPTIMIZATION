# V0.2.0 summary — tooling integration

> 2026-08-27. Turned [07-TOOLING-UPDATES.md](../07-TOOLING-UPDATES.md)'s survey into working code: one
> Python hook per external dataset/tool, a working `qpgrid` conda env, an offline proof notebook, and
> a token-free web dashboard. Full plan + adopt/reject rationale: [08-TOOLING-INTEGRATION.md](../08-TOOLING-INTEGRATION.md).

## What changed

**Environment** — `environment.yml` rebuilt and actually verified (a `qpgrid` conda env did not exist before; V0.0.1/V0.1.0 used throwaway venvs):
- Python 3.11 → **3.12** (highest that satisfies Classiq ≤3.13 *and* gridfm-datakit <3.13).
- `pandapower` / `pypsa` / `dwave-ocean-sdk` / `gridfm-datakit` moved to the `pip:` section — conda-forge lags (pandapower stops at 3.2.1, Ocean at 6.0.1). Env now resolves pandapower **3.5.4**, pypsa **1.3.0**, dwave-ocean **9.4.0**, gridfm-datakit **1.0.5** (needs `juliapkg<0.1.26`).
- `pandas` pinned `>=2.3,<3` (pandapower 3.5 breaks on pandas 3.0). Create with `--solver=libmamba` (classic solver takes >20 min).

**New hooks** (all follow the `data/*_to_pp.py` convention — source URL + verified format notes, `HAVE_<dep>` guards, `__main__` demo, no hardcoded tokens):

| Module | Tool | Verified |
|---|---|---|
| `data/opfdata_to_pp.py` | DeepMind OPFData (GCS bucket) | case14 converts; runpp at the shipped AC-OPF setpoints reproduces \|V\| to **RMS 0.006 pu** |
| `data/pglearn_to_pp.py` | PGLearn (HF, primal+dual HDF5) | case14 `data` block → pandapower, runpp converges; reads reference primal/dual + `meta.h5` |
| `data/gridfm_datakit_hook.py` | gridfm-datakit (PF/OPF generator) | schema-valid config; a real LIVE run generated 3-scenario PF parquet for case14 (one-time Julia install) |
| `data/openinframap_hook.py` | Overpass + OpenInfraMap tiles | live Overpass query → 671-feature GeoJSON; `pp_net_to_geojson()` for the web map |
| `data/hifld_archive.py` | HIFLD Open (dead → archive) | resolves Data-Rescue / DataLumos / source.coop-parquet mirrors |
| `data/climrr_overlay.py` | ClimRR Fire Weather Index | ArcGIS REST query (server 500s intermittently — synthetic CA fixture fallback); bus→cell hazard join |
| `pypsa_bridge.py` | PyPSA v1.0 stochastic | `pp → pypsa.Network`; two-stage stochastic solve, robust gen sizing, CVaR risk premium |

**Proof** — `notebooks/tooling_integration.ipynb`: one section per hook, runs against `data/fixtures/` with **no network** (each has a `LIVE=True` opt-in), `jupyter nbconvert --execute` clean, 8/8 passing. `web/tooling_dashboard.html`: MapLibre + OpenInfraMap vector tiles + OSM raster (no Mapbox token), status matrix from `web/data/tooling_status.json`, converted transnet-California network + ClimRR choropleth overlaid; rendered screenshot at `web/tooling_dashboard_preview.png`.

**Web map rewrite** (2026-08-28) — `web/opengridmap_source.html` (the one the mobile app embeds) was down: it needed a Mapbox token (placeholder since the token purge). Rewritten to MapLibre GL + no-key tiles (Esri basemaps + OpenInfraMap vector), keeping all original features (voltage-tiered lines, substations/plants, filter / basemap-switch / bounding-box panels, click popups) and adding the QPGrid pipeline overlays (converted network, Overpass-hook GeoJSON, ClimRR choropleth) from `web/data/`. Preview: `web/opengridmap_preview.png`.

**Plotting → Plotly** (2026-08-27/28) — every plot in the repo is Plotly now (charts: `plotly.graph_objects`; grid networks: `pandapower.plotting.plotly`). Zero matplotlib references in repo code (it stays in the env as a pandapower dependency). One-line rule added to CLAUDE.md / AGENTS.md / README.md. `quantum_util.py` Bloch spheres, `util.py` savefig, the QUBO/pp_learn notebooks all converted.

**Incidental fix** — `data/osm_to_pp.py:network_from_OSM()` referenced `net['bus_geodata']`, a table pandapower 3.0 removed; the f7503c44 "finish the stub" commit was written/tested pre-3.0. Now reads `net.bus['geo']`.
